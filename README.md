# Ответы · ДЗ 4 по веб-разработке VK Education

Учебный сайт вопросов и ответов на Django 5.2 и PostgreSQL 16. Здесь можно зарегистрироваться, задать вопрос, ответить другому участнику и проголосовать. Автор вопроса может отметить один правильный ответ.

## Подготовка окружения

Команды выполняются из корня ветки `hw-4`. Создайте два файла конфигурации. В примере ниже Python генерирует новый секрет Django и пароль БД. Команды рассчитаны на первый запуск.

```bash
python3 - <<'PY'
from pathlib import Path
from secrets import token_urlsafe

template = Path(".env.example").read_text()
template = template.replace("DJANGO_SECRET_KEY=\n", f"DJANGO_SECRET_KEY={token_urlsafe(48)}\n")
template = template.replace("POSTGRES_PASSWORD=\n", f"POSTGRES_PASSWORD={token_urlsafe(32)}\n")
for filename, host in [(".env.local", "127.0.0.1"), (".env.docker", "db")]:
    with open(filename, "x") as env_file:
        env_file.write(template.replace("POSTGRES_HOST=127.0.0.1", f"POSTGRES_HOST={host}"))
PY
```

## Запуск в Docker

```bash
docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```

Откройте [сайт через nginx](http://localhost:8080/) или [админку](http://localhost:8080/admin/). Nginx раздаёт файлы из томов `static` и `media`, а запросы приложения передаёт Django. Прямой адрес Django для отладки — http://localhost:8000/. При запуске веб-контейнер дожидается готовности PostgreSQL и применяет миграции. Команда `docker compose down` останавливает сервисы. Именованный том `pgdata` хранит БД между запусками.

## Запуск Django на компьютере

Понадобятся Python 3.12 и PostgreSQL. Можно поднять только базу через Compose и запустить Django локально.

```bash
docker compose up -d --wait db
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Для уже установленного PostgreSQL укажите в `.env.local` имя существующей базы, её владельца, пароль и порт. При таком запуске шаг с Compose можно пропустить.

## Как проверить ДЗ 4

1. Откройте `/signup/`, введите логин, почту, имя и пароль. После регистрации откроется главная страница. Ссылка с именем в шапке ведёт в `/profile/`, где можно обновить данные и загрузить PNG, JPEG или WebP до 2 МБ.
2. На `/ask/` опубликуйте вопрос с тегами через запятую. После публикации откроется вопрос. Отправка ответа ведёт на его страницу с якорем `#answer-<id>`. Для проверки второй страницы удобно использовать вопрос с 30 и более ответами после `fill_db`.
3. Нажмите плюс или минус рядом с вопросом или ответом. Рейтинг обновится без перезагрузки. Свой голос можно изменить, выбрав противоположную оценку. Автор вопроса может выбрать правильный ответ или снять отметку.
4. Нажмите «Выйти» на странице вопроса. Страница останется открытой, кнопки голосования и отправки ответа станут недоступны. Ссылка «Войти» вернёт на этот вопрос после авторизации. Прямой переход гостя на `/ask/` или `/profile/` сначала откроет форму входа.

Все изменения записываются в PostgreSQL. Миграции сохраняют лайки из ДЗ 3 как голоса +1. Команды запуска из предыдущих шагов работают и при пустой базе.

## Тестовые данные и страницы

Сразу после миграций сайт работает с пустой базой. Для быстрого просмотра выполните `python manage.py fill_db 5`. Для проверки объёма из задания выполните команду ниже. В Docker добавьте перед ней `docker compose exec web`.

```bash
python manage.py fill_db 10000
```

Каждый запуск добавляет записи одной транзакцией. При коэффициенте 10 000 добавится 10 000 пользователей с профилями, 100 000 вопросов, 1 000 000 ответов, 10 000 тегов и 2 000 000 лайков. Если нужны значения строго выше этих порогов за один запуск, укажите 10 001. Минимальный коэффициент для пустой базы равен 2. Для одного пользователя есть только 110 разных объектов на требуемые 200 лайков.

| Адрес | Что проверить |
| --- | --- |
| `/` | Новые вопросы по дате, поиск по заголовку и тексту, 20 вопросов на страницу |
| `/hot/` | Вопросы по сумме оценок, при равенстве выше новый вопрос |
| `/tag/<тег>/` | Вопросы с выбранным тегом. Ссылка есть в карточке и боковой колонке |
| `/question/<id>/` | Текст вопроса, число и список ответов, 30 ответов на страницу |
| `/admin/` | Управление записями, профиль внутри пользователя, ответы внутри вопроса |

Добавьте `?page=2` к адресу для перехода на вторую страницу. Генератор создаёт по 37 ответов у первого вопроса каждой десятки. Отсутствующий вопрос или тег возвращает HTTP 404. Отладочная панель подключается при `DJANGO_DEBUG=1`.

Для проверки регистрации, разрешений, аватаров, форм, голосования, пагинации и запросов к БД выполните `DJANGO_DEBUG=0 python manage.py test`. Пользователю PostgreSQL для запуска тестов требуется право создания тестовой базы.
